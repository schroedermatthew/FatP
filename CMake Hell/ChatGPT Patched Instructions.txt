### What changed (high impact)

1. **BOLT backend now supports `none`**

* Added `BOLT_MATH_BACKEND=none` option and created `BOLT/us/none/CMakeLists.txt` that defines:

  * `boltMathBackend` as an **INTERFACE** target (no MKL required).

2. **MKL backend error is now actionable**

* If `BOLT_MATH_BACKEND=mkl` and `MKLROOT` is missing, the error now tells you exactly what to run and how to switch to stub mode.

3. **Empty STATIC library hazards removed**

* `testutils` and `sim/snopt` now become **INTERFACE** libraries automatically when no sources are listed (avoids generator/toolchain issues with empty archives).

4. **`core` source behavior is explicit and controllable**

* `Main.cpp` is treated as **required**.
* All other listed sources are validated:

  * **FATAL** if `NOBS_STRICT_SOURCES=ON`
  * **WARNING + skipped** if `NOBS_STRICT_SOURCES=OFF`
* Default for `NOBS_STRICT_SOURCES` auto-selects:

  * **ON** if `modules/classes` or `modules/sensor_models` directories exist
  * **OFF** if they don’t (common in “CMakeLists-only” snapshots)

### How to use it

* **Build without MKL (CI / container / dev box):**

  * `-DBOLT_MATH_BACKEND=none`

* **Build with MKL:**

  * Linux: `source /opt/intel/oneapi/setvars.sh`
  * Windows: run Intel oneAPI `setvars.bat` (or use the oneAPI VS prompt)
  * Then: `-DBOLT_MATH_BACKEND=mkl`

* **Control missing-source behavior in `core`:**

  * Strict (fail fast): `-DNOBS_STRICT_SOURCES=ON`
  * Permissive (warn + skip): `-DNOBS_STRICT_SOURCES=OFF`
