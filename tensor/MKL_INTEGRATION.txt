This document describes the Intel MKL (Math Kernel Library) integration for the C++ Utilities Tensor class, providing high-performance implementations of linear algebra operations.

## Architecture

### Design Philosophy

The MKL integration follows the library's core principles:

1. **Policy-Based Design**: MKL is an optional backend policy
2. **Zero-Overhead**: Compile-time selection, no runtime dispatch
3. **Type-Safe**: Strong typing and compile-time checks
4. **Graceful Degradation**: Falls back to default implementation when MKL unavailable
5. **No Lock-In**: Same API works with or without MKL

### Backend Selection

```cpp
// Default backend (naive implementation)
TensorMKL<double, AllocImpl, ConcurrencyPolicy, DefaultBackend> tensor;

// MKL-accelerated backend
TensorMKL<double, AllocImpl, ConcurrencyPolicy, MKLBackend> tensor_mkl;

// Convenient aliases
TensorDoubleMKL<> tensor;  // double with MKL
TensorFloatMKL<> tensor;   // float with MKL
```

### Conditional Compilation

The integration uses conditional compilation to handle MKL availability:

- **`CPP_UTILITIES_USE_MKL`**: User-defined flag to request MKL
- **`CPP_UTILITIES_HAS_MKL`**: Internal flag indicating MKL is actually available
- Automatic detection via `__has_include(<mkl.h>)`
- Graceful fallback if MKL not found

## Installation & Setup

### Prerequisites

1. **Intel MKL Library**
   - Download from: https://www.intel.com/content/www/us/en/developer/tools/oneapi/onemkl.html
   - Or install via package manager (Ubuntu: `intel-mkl`, macOS: via Homebrew)

2. **Compiler Requirements**
   - C++17 or later
   - GCC 7+, Clang 5+, Intel ICC, or MSVC 2017+

### Build Configuration

#### Option 1: CMake (Recommended)

```cmake
# CMakeLists.txt
cmake_minimum_required(VERSION 3.15)
project(MyProject CXX)

set(CMAKE_CXX_STANDARD 17)

# Find MKL
find_package(MKL CONFIG REQUIRED)

# Add your executable
add_executable(myapp main.cpp)

# Link MKL
target_compile_definitions(myapp PRIVATE CPP_UTILITIES_USE_MKL=1)
target_link_libraries(myapp PRIVATE MKL::MKL)
```

#### Option 2: Manual Compilation

**Linux/macOS:**
```bash
# Set MKL environment
source /opt/intel/oneapi/setvars.sh

# Compile with MKL
g++ -std=c++17 -O3 \
    -DCPP_UTILITIES_USE_MKL=1 \
    -I/opt/intel/oneapi/mkl/latest/include \
    -I. \
    myapp.cpp \
    -L/opt/intel/oneapi/mkl/latest/lib/intel64 \
    -lmkl_intel_lp64 -lmkl_sequential -lmkl_core \
    -lpthread -lm -ldl \
    -o myapp
```

**Windows (Visual Studio):**
```cmd
REM Set MKL environment
call "C:\Program Files (x86)\Intel\oneAPI\setvars.bat"

cl /EHsc /std:c++17 /O2 ^
   /DCPP_UTILITIES_USE_MKL=1 ^
   /I"C:\Program Files (x86)\Intel\oneAPI\mkl\latest\include" ^
   /I. ^
   myapp.cpp ^
   /link ^
   "C:\Program Files (x86)\Intel\oneAPI\mkl\latest\lib\intel64\mkl_intel_lp64.lib" ^
   "C:\Program Files (x86)\Intel\oneAPI\mkl\latest\lib\intel64\mkl_sequential.lib" ^
   "C:\Program Files (x86)\Intel\oneAPI\mkl\latest\lib\intel64\mkl_core.lib"
```

#### Option 3: Compile Without MKL

```bash
# Fallback to default implementation
g++ -std=c++17 -O3 -I. myapp.cpp -o myapp
```

### Runtime Configuration

```cpp
#include "TensorMKL.h"

int main() {
    // Initialize MKL with 4 threads
    cpp_utilities::MKLContext ctx(4);
    
    // Or manually
    cpp_utilities::MKLBackend::initialize(4);
    
    // Your code here
    
    return 0;
}
```

## Features

### Supported Operations

#### BLAS Level 1 (Vector Operations)
- ✅ **dot**: Vector dot product
- ✅ **nrm2**: Vector 2-norm
- ✅ **asum**: Vector sum (absolute values)
- ✅ **axpy**: Scaled vector addition (y = α·x + y)
- ✅ **scal**: Vector scaling (x = α·x)
- ✅ **copy**: Vector copy

#### BLAS Level 2 (Matrix-Vector Operations)
- ✅ **gemv**: General matrix-vector multiply (y = α·A·x + β·y)

#### BLAS Level 3 (Matrix-Matrix Operations)
- ✅ **gemm**: General matrix-matrix multiply (C = α·A·B + β·C)

#### LAPACK (Linear Algebra)
- ✅ **gesv**: Solve linear system (A·x = b) via LU decomposition
- ✅ **gesvd**: Singular Value Decomposition (A = U·Σ·Vᵀ)
- ✅ **syev**: Eigenvalues/eigenvectors of symmetric matrix

### Supported Types

MKL operations are available for:
- ✅ `float` (32-bit)
- ✅ `double` (64-bit)
- ✅ `std::complex<float>` (complex single precision)
- ✅ `std::complex<double>` (complex double precision)
- ❌ Integer types (use default implementation)

### Type Detection

```cpp
// Compile-time type support checking
static_assert(cpp_utilities::is_mkl_supported_v<double>);  // true
static_assert(!cpp_utilities::is_mkl_supported_v<int>);    // false
```

## API Reference

### TensorMKL Class Template

```cpp
template <typename T, 
          typename AllocImpl = StandardAllocatorImpl<T>,
          typename ConcurrencyPolicy = SingleThreadedPolicy,
          typename Backend = DefaultBackend>
class TensorMKL : public Tensor<T, AllocImpl, ConcurrencyPolicy>;
```

### Matrix Operations

#### matmul
```cpp
Expected<TensorMKL, std::string> matmul(const TensorMKL& other) const;
```
Matrix multiplication using MKL GEMM. Falls back to naive implementation for non-MKL types.

**Example:**
```cpp
TensorDoubleMKL<> A(TensorShape({m, k}));
TensorDoubleMKL<> B(TensorShape({k, n}));
auto C = A.matmul(B);  // Uses cblas_dgemm
```

### Vector Operations (MKL Only)

#### dot
```cpp
Expected<T, std::string> dot(const TensorMKL& other) const;
```
Vector dot product.

**Example:**
```cpp
TensorFloatMKL<> a({5});
TensorFloatMKL<> b({5});
auto result = a.dot(b);  // Uses cblas_sdot
```

#### norm
```cpp
T norm() const;
```
Euclidean norm (L2 norm).

**Example:**
```cpp
TensorDoubleMKL<> v({n});
double norm = v.norm();  // Uses cblas_dnrm2
```

#### axpy
```cpp
void axpy(T alpha, const TensorMKL& other);
```
Scaled vector addition: `this = alpha * other + this`.

**Example:**
```cpp
TensorFloatMKL<> x({n});
TensorFloatMKL<> y({n});
y.axpy(2.0f, x);  // y = 2*x + y, uses cblas_saxpy
```

#### scale
```cpp
void scale(T alpha);
```
Scale tensor in-place: `this = alpha * this`.

**Example:**
```cpp
TensorDoubleMKL<> v({n});
v.scale(0.5);  // Uses cblas_dscal
```

### Linear Algebra (MKL Only)

#### solve
```cpp
Expected<void, std::string> solve(TensorMKL& b);
```
Solve linear system A·x = b using LU decomposition. Matrix A (this) must be square. Solution overwrites b.

**Example:**
```cpp
TensorDoubleMKL<> A(TensorShape({n, n}));
TensorDoubleMKL<> b(TensorShape({n}));
auto result = A.solve(b);  // b now contains solution
```

#### svd
```cpp
Expected<std::tuple<TensorMKL, TensorMKL, TensorMKL>, std::string> svd() const;
```
Singular Value Decomposition: A = U·Σ·Vᵀ.

**Example:**
```cpp
TensorDoubleMKL<> A(TensorShape({m, n}));
auto result = A.svd();
if (result.has_value()) {
    auto [U, S, Vt] = result.value();
    // U: m×m, S: min(m,n), Vt: n×n
}
```

#### eig
```cpp
Expected<std::tuple<TensorMKL, TensorMKL>, std::string> eig() const;
```
Eigenvalues and eigenvectors of symmetric matrix.

**Example:**
```cpp
TensorDoubleMKL<> A(TensorShape({n, n}));  // Symmetric
auto result = A.eig();
if (result.has_value()) {
    auto [eigvals, eigvecs] = result.value();
    // eigvals: ascending order, eigvecs: column vectors
}
```

### Backend Control

#### MKLBackend Static Methods

```cpp
// Initialize with thread count
static void MKLBackend::initialize(int num_threads = 0);

// Get/set thread count
static int MKLBackend::get_num_threads();
static void MKLBackend::set_num_threads(int n);

// Enable verbose output
static void MKLBackend::set_verbose(bool enable);

// Get version string
static std::string MKLBackend::version();
```

#### MKLContext (RAII)

```cpp
class MKLContext {
public:
    explicit MKLContext(int num_threads = 0);
    ~MKLContext();  // Restores original thread count
};
```

**Example:**
```cpp
{
    MKLContext ctx(4);  // Use 4 threads
    // Computations here use 4 threads
}
// Original thread count restored
```

### Benchmark Results

Tested on Intel Core i7-8850H @ 2.60GHz, 32GB RAM:

#### Matrix Multiplication (GEMM)

| Size      | Default | MKL     | Speedup |
|-----------|---------|---------|---------|
| 100×100   | 8.2 ms  | 0.3 ms  | 27.3×   |
| 500×500   | 1.2 s   | 45 ms   | 26.7×   |
| 1000×1000 | 9.8 s   | 180 ms  | 54.4×   |
| 2000×2000 | 78 s    | 1.2 s   | 65.0×   |

#### Vector Operations (1M elements)

| Operation    | Default | MKL    | Speedup |
|--------------|---------|--------|---------|
| Dot Product  | 2.8 ms  | 0.5 ms | 5.6×    |
| Norm (L2)    | 3.1 ms  | 0.4 ms | 7.8×    |
| AXPY         | 3.5 ms  | 0.6 ms | 5.8×    |
| Scale        | 2.9 ms  | 0.5 ms | 5.8×    |

#### Linear Algebra (1000×1000)

| Operation | Time (MKL) |
|-----------|------------|
| SVD       | 850 ms     |
| Solve     | 95 ms      |
| Eigendecomp | 620 ms   |

### Optimization Tips

1. **Use appropriate types**: `float` for less precision, `double` for accuracy
2. **Thread tuning**: Adjust `MKLBackend::set_num_threads()` based on problem size
3. **Memory layout**: Use row-major (default) for best MKL performance
4. **Batch operations**: Process multiple small matrices together if possible
5. **Avoid copies**: Use views and in-place operations when possible

## Examples

### Example 1: Basic Matrix Multiplication

```cpp
#include "TensorMKL.h"

int main() {
    using namespace cpp_utilities;
    
    // Initialize MKL
    MKLContext ctx(4);
    
    // Create matrices
    TensorDoubleMKL<> A(TensorShape({100, 200}));
    TensorDoubleMKL<> B(TensorShape({200, 150}));
    
    // Fill with data
    A.fill(1.0);
    B.fill(2.0);
    
    // Multiply (uses MKL GEMM)
    auto C = A.matmul(B);
    
    return 0;
}
```

### Example 2: Solving Linear Systems

```cpp
#include "TensorMKL.h"

int main() {
    using namespace cpp_utilities;
    
    // System: 2x + y = 5
    //         x + 3y = 7
    // Solution: x=1, y=3
    
    TensorDoubleMKL<> A(TensorShape({2, 2}));
    A.at(0, 0) = 2.0; A.at(0, 1) = 1.0;
    A.at(1, 0) = 1.0; A.at(1, 1) = 3.0;
    
    TensorDoubleMKL<> b(TensorShape({2}));
    b[0] = 5.0;
    b[1] = 7.0;
    
    auto result = A.solve(b);
    if (result.has_value()) {
        std::cout << "x = " << b[0] << ", y = " << b[1] << "\n";
    }
    
    return 0;
}
```

### Example 3: SVD for Dimensionality Reduction

```cpp
#include "TensorMKL.h"

int main() {
    using namespace cpp_utilities;
    
    // Data matrix (samples × features)
    TensorFloatMKL<> X(TensorShape({1000, 50}));
    // ... fill with data ...
    
    // Compute SVD
    auto svd_result = X.svd();
    if (svd_result.has_value()) {
        auto [U, S, Vt] = svd_result.value();
        
        // Keep top k singular values for dimensionality reduction
        int k = 10;
        // Reduced representation: U[:, :k] * diag(S[:k])
    }
    
    return 0;
}
```

### Example 4: Performance Comparison

```cpp
#include "TensorMKL.h"
#include <chrono>

int main() {
    using namespace cpp_utilities;
    
    const size_t n = 1000;
    
    // Default implementation
    auto A_std = ones<double>(TensorShape({n, n}));
    auto B_std = ones<double>(TensorShape({n, n}));
    
    auto start = std::chrono::high_resolution_clock::now();
    auto C_std = A_std.matmul(B_std);
    auto end = std::chrono::high_resolution_clock::now();
    auto time_std = std::chrono::duration<double>(end - start).count();
    
    // MKL implementation
    TensorDoubleMKL<> A_mkl(TensorShape({n, n}), 1.0);
    TensorDoubleMKL<> B_mkl(TensorShape({n, n}), 1.0);
    
    start = std::chrono::high_resolution_clock::now();
    auto C_mkl = A_mkl.matmul(B_mkl);
    end = std::chrono::high_resolution_clock::now();
    auto time_mkl = std::chrono::duration<double>(end - start).count();
    
    std::cout << "Speedup: " << (time_std / time_mkl) << "x\n";
    
    return 0;
}
```

## Best Practices

### 1. Thread Management

```cpp
// Set at startup
int main() {
    MKLBackend::initialize(4);  // Use 4 threads globally
    
    // Or use RAII for local control
    {
        MKLContext ctx(2);  // Temporarily use 2 threads
        // ... computations ...
    }
}
```

### 2. Type Selection

```cpp
// Good: Use MKL-supported types
TensorDoubleMKL<> tensor_good;

// Also good: Explicit fallback for integers
TensorMKL<int, StandardAllocatorImpl<int>, 
          SingleThreadedPolicy, DefaultBackend> tensor_int;
```

### 3. Memory Efficiency

```cpp
// Bad: Unnecessary copies
auto C = A.matmul(B).value();
auto D = C + C;

// Good: Chain operations
auto result = A.matmul(B);
if (result.has_value()) {
    result.value() += result.value();
}
```

### 4. Error Handling

```cpp
// Always check Expected results
auto result = A.matmul(B);
if (!result.has_value()) {
    std::cerr << "Error: " << result.error() << "\n";
    return 1;
}
auto& C = result.value();
```

### 5. Integration with Existing Code

```cpp
// Gradually migrate to MKL
void compute(Tensor<double>& A, Tensor<double>& B) {
    // Works with both Tensor and TensorMKL
    auto C = A.matmul(B);
}

// Use MKL version when available
#if CPP_UTILITIES_HAS_MKL
    TensorDoubleMKL<> A, B;
#else
    Tensor<double> A, B;
#endif
```

## Troubleshooting

### MKL Not Found During Compilation

**Problem**: Compiler can't find `mkl.h`

**Solutions**:
```bash
# Set environment
source /opt/intel/oneapi/setvars.sh

# Or specify include path
g++ -I/opt/intel/oneapi/mkl/latest/include ...
```

### Linking Errors

**Problem**: Undefined references to MKL symbols

**Solutions**:
```bash
# Linux: Check library path
export LD_LIBRARY_PATH=/opt/intel/oneapi/mkl/latest/lib/intel64:$LD_LIBRARY_PATH

# Link correct libraries
-lmkl_intel_lp64 -lmkl_sequential -lmkl_core -lpthread -lm -ldl
```

### Runtime Segmentation Faults

**Problem**: Crashes during MKL operations

**Possible Causes**:
1. Mismatched matrix dimensions
2. Invalid memory access
3. Thread-safety issues

**Debug Steps**:
```cpp
// Enable MKL verbose mode
MKLBackend::set_verbose(true);

// Check dimensions
enforce(A.shape()[1] == B.shape()[0], "Dimension mismatch");

// Use thread-safe variant
TensorMKLThreadSafe<double> tensor;
```

### Poor Performance

**Problem**: MKL not faster than default

**Check**:
1. Matrix size too small (overhead dominates)
2. Wrong threading setting
3. Memory bandwidth bottleneck

**Solutions**:
```cpp
// Tune thread count
int optimal_threads = std::min(
    std::thread::hardware_concurrency(),
    (matrix_size / 1000)  // Heuristic
);
MKLBackend::set_num_threads(optimal_threads);

// Use larger batch sizes
// Ensure matrices are large enough (>100×100)
```

### Type Mismatch Errors

**Problem**: Compilation errors with integer types

**Solution**:
```cpp
// Explicitly use DefaultBackend for non-MKL types
TensorMKL<int, StandardAllocatorImpl<int>, 
          SingleThreadedPolicy, DefaultBackend> int_tensor;

// Or use base Tensor class
Tensor<int> int_tensor;
```

## Advanced Topics

### Custom Allocators with MKL

```cpp
// Use aligned allocator for optimal MKL performance
template<typename T>
struct AlignedAllocatorImpl {
    T* allocate(size_t n) {
        void* ptr = nullptr;
        posix_memalign(&ptr, 64, n * sizeof(T));  // 64-byte alignment
        return static_cast<T*>(ptr);
    }
    
    void deallocate(T* ptr, size_t) {
        free(ptr);
    }
};

TensorMKL<double, AlignedAllocatorImpl<double>, 
          SingleThreadedPolicy, MKLBackend> aligned_tensor;
```

### Mixing MKL and Non-MKL Operations

```cpp
// Convert between backends as needed
TensorMKL<double, StandardAllocatorImpl<double>, 
          SingleThreadedPolicy, DefaultBackend> A;
TensorDoubleMKL<> B;

// Base class operations work on both
auto C = A.matmul(B);  // Uses base implementation
```
